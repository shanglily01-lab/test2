# 超级大脑场景化复盘与改造方案（2026-08-11）

## 1. 结论摘要

这次问题不是单一 bug，而是 BRAIN 仍然缺少一套稳定的“行情场景状态机”。当前系统已经有 Playbook、Big4、胜率、edge、限价、防插针、退出等组件，但这些组件更像串联硬门槛，缺少场景层统一调度：

- 哪些行情只允许多头；
- 哪些行情只允许空头；
- 哪些行情只能影子观察；
- 哪些行情必须停止开仓并优先收缩已有仓位；
- 不同场景应使用不同仓位、限价方式、持仓时长、止损止盈和退出优先级。

因此，不能继续“发现一个漏空就放宽一个空头门槛”或“某天亏了就关一个 Playbook”。需要把 BRAIN 改成：

```text
市场场景识别 -> Playbook 允许表 -> 方向/胜率/edge 仲裁 -> 执行策略 -> 持仓生命周期策略 -> 事后归因与自动降权
```

### 2.3 机会识别与开仓门控

过去 36 小时 BRAIN 识别出大量 SHORT 候选，但 0 笔开仓。主要原因：

- 旧运行版本中 A2/C1 仍被 `playbook_A2` / `playbook_C1` 拒绝，说明服务未加载最新代码或未重启；
- 新逻辑要求 Big4 必须 `SHORT`，而 2026-08-10 20:02 之后 Big4 多数时间是 `FLAT`，导致个币明显偏空也被 `short_needs_big4_short` 拦截；
- DeepSeek explore/predict 在部分时间被关闭，BRAIN 成为主路径，但 BRAIN 自身方向偏置仍以 A1 LONG 为主。

## 3. 根因

### 3.1 缺少场景状态机

现有 Big4 只有 `LONG/SHORT/FLAT` 和 `big4_ok`，但真实行情至少需要区分：

- 趋势上涨；
- 趋势下跌；
- 瀑布急跌；
- 急跌后反弹；
- 高波动震荡；
- 低波动无趋势；
- 单币独立强弱；
- 市场从多转空或从空转多的过渡期。

目前多个截然不同的行情被压缩成 `Big4=FLAT`，这会同时误杀强空头、误放 A1 多头。

### 3.2 Playbook 没有场景允许表

当前 `TRADEABLE_PLAYBOOKS` 只解决“哪些标签能开”，没有回答“在哪个行情里能开”。A1 在趋势上涨有效，在下跌切换期危险；A2 在普通震荡负期望，在强下跌趋势中可能有价值；C1 直接追破位历史表现很差，除非另加确认。

### 3.3 胜率口径过粗

`brain_winrate.py` 近 7 天、4h forward、方向对即算赢，这个口径适合粗过滤，不适合作最终开仓依据。问题：

- 不区分 Playbook；
- 不区分行情场景；
- 不区分开仓执行方式；
- 不区分真实盈亏比；
- 不区分计划到期、trail、SL 的退出质量。

### 3.4 执行层与行情速度不匹配

BRAIN 强制限价并超时取消是防插针正确方向，但不同场景应不同：

- A1 回踩：限价合理；
- A2 反抽做空：限价合理；
- C1 向下破位：一律挂在市价上方容易错过主跌段；
- 瀑布急跌：需要“确认后追随型限价”或“小仓快速试探”，不能完全等待反抽。

### 3.5 退出层没有场景意识

目前主要按 ATR 和 Playbook 家族给 SL/TP/hold，再用 trail、美元熔断、计划到期兜底。问题：

- A1 趋势仓和 B1 反弹仓不应同一套到期逻辑；
- C 类破位仓失败通常应很快撤，不应等计划到期；
- 瀑布空头如果盈利，应更早分批锁利，避免 V 反吞掉；
- 计划到期亏损巨大，说明持仓到期不是安全退出，而是延迟认错。

## 4. 场景矩阵

### 4.1 Regime 枚举

建议新增 `brain_market_regime.py`，输出以下场景：

| Regime | 说明 | 交易姿态 |
|---|---|---|
| `BULL_TREND` | Big4 多头，市场量价健康 | 主做 A1，多头突破谨慎 |
| `BEAR_TREND` | Big4 空头，市场量价健康 | 允许 A2，小仓 C1，禁止 A1 |
| `CRASH_DOWN` | 15m/1h 急跌，波动放大 | 禁止 A1/B1 抄底，允许强 C1/A2 小仓试空 |
| `PANIC_REBOUND` | 急跌后长下影/放量反弹 | 禁止追空，B1/C2 只影子或极小仓 |
| `RANGE_CHOP` | Big4 FLAT 但波动足，方向反复 | 仅允许高 edge A1/A2，仓位折半，缩短 hold |
| `LOW_VOL_NO_TRADE` | Big4 疲软或低波动低量 | 不开仓，只落库 |
| `TOKEN_DIVERGENCE` | Big4 FLAT，但单币 1h/15m 强趋势 | 允许强单币 A1/A2/C1 豁免，小仓 |
| `TRANSITION` | Big4 刚从 LONG 转 FLAT/SHORT 或反向 | 降低开仓频率，禁止逆新方向 |

## 5. Playbook 处理建议

### A1 多头趋势回踩

保留，但加场景限制：

- 只在 `BULL_TREND`、`RANGE_CHOP` 高 edge、`TOKEN_DIVERGENCE` 强多时开；
- `BEAR_TREND`、`CRASH_DOWN`、`TRANSITION_TO_SHORT` 禁止；
- 当过去 24h A1 日内 PnL < -300U 或胜率 < 45%，自动降仓或暂停；
- A1 虽然 30 天正期望，但 2026-08-10 的 -618U 说明必须有日内熔断。

### A2 空头趋势反抽

不应恢复大仓常规开。建议：

- 只在 `BEAR_TREND` 或 `TOKEN_DIVERGENCE` 强空允许；
- 必须 1h/15m 同空，且不能贴近短线极端低点追空；
- 仓位保持 0.35-0.50x；
- 反抽限价可以保留；
- 如果 30 天 A2 仍负期望，必须继续小仓试点，不可放大。

### C1 向下破位确认

当前历史表现最差，不能因为漏空就直接打开。

建议：

- C1 默认影子；
- 只在 `CRASH_DOWN` 或 `BEAR_TREND` 下，且同时满足 `volume_expand_down + break_support + h1/m15 SHORT` 才小仓；
- 不允许“仅 break_support”开仓；
- 不允许计划到期扛单，失败应在 15-30m 内撤；
- 单独统计 C1 的 shadow 4h 和真实成交 PnL，至少 30 笔后再决定放宽。

### B1/C2 暴跌反弹

这类最容易抄底接刀。建议：

- `CRASH_DOWN` 中禁止 B1 实开；
- 只有进入 `PANIC_REBOUND`，且 15m 不再创新低、放量收回关键位，才允许极小仓；
- 退出必须快，不能用 A 类 hold。

### B2/B3/C4 空头反转类

当前不应主路径实开：

- B2 保持影子，等待 shadow 胜率与盈亏比；
- B3/C4 需要重构定义，避免把普通上影噪音当顶部；
- 若 C4 后续样本显示高盈亏比，可作为“小样本观察 playbook”。

## 6. 入场与执行改造

### 6.1 新增执行模式

| 执行模式 | 适用 | 行为 |
|---|---|---|
| `pullback_limit` | A1/A2 | 按回踩/反抽偏移挂限价 |
| `breakout_confirm_limit` | C1/C3 | 确认破位后，在回抽不破位处挂限价 |
| `crash_probe_limit` | CRASH_DOWN 强 C1 | 小仓，限价贴近市价但仍禁止市价 |
| `shadow_only` | 未验证 playbook | 只落库，不开 |

### 6.2 OPENED 语义要拆分

当前机会表 `OPENED` 代表已挂 PENDING 限价，不代表成交。建议新增或明确字段：

- `decision=ORDER_PLACED / FILLED / EXPIRED / SKIPPED`；
- `fill_latency_sec`；
- `missed_move_pct`：挂单未成交后 30m/4h 实际方向收益；
- `execution_quality`：成交后是否立即反向、是否追太深。

否则会混淆“策略判断对了但没成交”和“策略判断错了”。

## 7. 退出改造

### 7.1 先处理最大亏损来源

计划到期退出当前是最大问题之一。建议：

- 如果到期时浮亏，不应统一强平，而应追溯原因：入场后从未盈利、盈利回吐、震荡无跟进、方向反转；
- 对 C 类和 B 类，计划到期前必须有更早的失败判定；
- 对 A1 趋势仓，到期若仍结构顺向可延长，但若 Big4/15m 已反向则提前平。

### 7.2 场景化退出表

| Playbook | 成功行为 | 失败行为 | 建议退出 |
|---|---|---|---|
| A1 | 回踩后继续趋势 | 15m 跌破回踩低点/Big4 转空 | trail 稍宽，失败早撤但非 5m 噪音 |
| A2 | 反抽后继续下行 | 15m 收回 EMA/前高 | 亏损更早撤，盈利快速锁 |
| B1/C2 | V 反 | 再创新低 | 极短 hold，失败立即撤 |
| C1 | 破位后加速 | 假跌破收回 | 15-30m 失败撤，不等计划到期 |
| C4 | 假突破回落 | 重新突破高点 | 快速止错，盈利分批锁 |

## 8. 监控与治理

必须新增“策略治理层”，不能靠手工复盘才发现：

1. `source_side_day_circuit`：同方向单日 PnL < -300U 或连续亏损 N 笔，暂停该方向；
2. `playbook_ev_registry`：按 playbook + regime + direction 记录 7/14/30 天胜率、均盈亏、profit factor；
3. `shadow_vs_real_report`：影子明显好于实开，查门槛/执行；影子差，继续关闭；
4. `code_version_heartbeat`：每个 tick 落库当前 git sha / config version，避免服务未重启仍跑旧逻辑；
5. `regime_transition_alert`：Big4 从 LONG/FLAT 转 SHORT 时，禁止旧方向新开，并提示已有仓位风险。

## 9. 分阶段落地

### Phase 0：立即止血

- 确认线上服务已重启并加载最新代码；
- 临时限制 A1：Big4 非 LONG 且非强单币多头时不再开 A1；
- 继续保持 C1 小仓或影子，不放大；
- 检查 DeepSeek explore/predict 是否应在对照期打开，避免它们和 BRAIN 互相污染归因。

### Phase 1：场景状态机

- 新增 `brain_market_regime.py`；
- 将 Big4 输出升级为 `regime + bias + volatility + transition_age`；
- 在 `brain_opportunities` 中落库 regime；
- 修改 orchestrator：先根据 regime 查 Playbook 允许表，再进入 win/edge/gate。

### Phase 2：Playbook EV 表

- 新增评估服务：`playbook + regime + side` 的 7/14/30 天表现；
- 胜率门从单纯方向胜率升级为 `EV gate`；
- 负期望 playbook 自动转 shadow。

### Phase 3：执行与退出分层

- 给每笔机会生成 `execution_mode`；
- 拆分 `ORDER_PLACED/FILLED/EXPIRED`；
- C 类失败快撤；
- A 类趋势延续或结构破坏退出；
- 到期退出必须按 playbook/regime 重判。

### Phase 4：自动治理

- 日内方向熔断；
- playbook 自动降权；
- 服务版本心跳；
- 每日自动生成 BRAIN 复盘摘要。

## 10. 当前已经修过但仍需纳入体系的点

2026-08-11 已提交 `50a15416`：

- 允许 Big4=FLAT 时强 A2/C1 单币空头通过；
- 要求 playbook A2/C1、confirmed、edge >= 0.80、1h/15m 同空、且有 crash/breakdown/放量下跌信号；
- 这只是止血补丁，不是完整方案。

完整方案必须继续推进场景状态机和 EV 治理，否则下次仍会在另一个门槛上出问题。
